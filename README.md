# hermes-slack-acl-memory-search

Плагин для [Hermes Agent](https://github.com/NousResearch/hermes-agent), ограничивающий поиск по памяти агента правами доступа пользователя в Slack.

Нужен, если Hermes работает как общий бот компании: без него любой сотрудник может попросить агента найти информацию из чужих разговоров, включая личные сообщения коллег.

## Проблема

Hermes хранит историю всех разговоров в одной базе `state.db`. Инструмент `session_search` ищет по ней **без учёта того, кто спрашивает**:

```python
session_search(query, role_filter, limit, db, current_session_id,
               session_id, around_message_id, window, sort, profile)
```

Ни одного параметра для ограничения по пользователю или каналу. Более того, аргумент `profile` позволяет обращаться к данным других профилей.

Профили Hermes (`multiplex_profiles` + `profile_routes`) изолируют credentials, `memories/` и наборы инструментов — но **не базу сессий**: `DEFAULT_DB_PATH` вычисляется при импорте модуля и замерзает на базовом пути, а gateway создаёт один экземпляр `SessionDB` и раздаёт его всем агентам.

### Воспроизведение

1. Роутим личку в профиль A, канал — в профиль B
2. В личке говорим боту кодовое слово
3. В канале спрашиваем: «какое кодовое слово я называл?»
4. Бот отвечает верно — он нашёл его через `session_search` в общей базе

## Решение

Плагин **подменяет** инструмент `session_search` собственной реализацией, которая перед выдачей результатов проверяет права спрашивающего.

Область поиска определяется тем, **кто увидит ответ**:

| Где спрашивают | Что ищет |
|---|---|
| канал `C…` | только сессии этого канала |
| личка `D…` пользователя U | сессии U + сессии каналов, где U состоит |
| неопределённый чат | отказ |

Ответ в канале виден всем участникам, поэтому туда не подтягивается личное. Ответ в личке виден только адресату, поэтому там допустим поиск по всему, что человек и так вправе прочитать.

### Почему подмена, а не хук

Все hook-механизмы Hermes (`pre_tool_call`, `transform_tool_result`, `tool_execution` middleware) **fail-open по конструкции**: исключение внутри хука подавляется, а документация прямо заявляет, что битый JSON и таймаут «never abort the agent loop». При сбое фильтра данные утекут.

Подмена инструмента ведёт себя иначе: если плагин не загрузился, инструмента нет вовсе. Худший исход — агент теряет умение искать, а не начинает искать без ограничений.

Плагин не переписывает логику поиска: он вызывает оригинальную функцию, подставив фильтрующий прокси вместо объекта базы данных.

## Установка

Требуется Hermes v0.19.0 или новее.

```yaml
# ~/.hermes/config.yaml
plugins:
  entries:
    hermes-slack-acl-memory-search:
      allow_tool_override: true

agent:
  disabled_toolsets: [session_search]
```

`disabled_toolsets` оставляется намеренно: если плагин однажды не загрузится, штатный нефильтрованный инструмент не подхватится вместо него.

## Ловушка при разработке плагинов с override

Handler должен быть **объявлен в `__init__.py`**, а не в подмодуле.

Hermes авторизует переопределение встроенного инструмента по `handler.__globals__["__name__"]` (`tools/registry.py`, `_plugin_owner_of`), но регистрирует разрешение только на корень пакета. Handler, объявленный в `tool.py`, разрешается в `<pkg>.tool`, политики для него нет, и регистрация отклоняется — с сообщением, которое указывает на ключи конфига, хотя они уже выставлены верно:

```
Tool registration REJECTED: plugin 'hermes_plugins.<pkg>.tool' attempted to
override built-in tool 'session_search' ... Set
plugins.entries.<plugin_id>.allow_tool_override: true in config.yaml
```

Поэтому `__init__.py` объявляет тонкую обёртку `tool_handler`, а вся логика остаётся в `tool.py`.

## Ограничения

Плагин закрывает поиск, но не заменяет остальные слои защиты:

- **База сессий физически одна.** Профиль с инструментом `terminal` прочитает её напрямую в обход плагина. Терминал должен оставаться только у доверенного круга.
- **Кэш членства в каналах** отстаёт на несколько минут: исключённый из приватного канала сотрудник это время ещё сможет искать по нему.
- **Память `memories/` общая внутри профиля** — плагин её не касается. Изоляция личных заметок требует отдельного профиля на человека.

## Тесты

```bash
python3 -m unittest discover tests -v
```

Тесты не требуют установленного Hermes — логика фильтрации проверяется на заглушке базы. Покрыты: изоляция каналов, отказ на чужую личку (воспроизведение исходной утечки), наследование по цепочке родителей, запрет произвольного SQL, сужение области при недоступности Slack.
